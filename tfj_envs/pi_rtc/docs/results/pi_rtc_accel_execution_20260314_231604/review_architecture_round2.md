# PI05 RTC Round 2 Architecture Review

## 结论

- 本轮整改已经闭合了上一轮大部分功能性问题，但没有把“shared helper 收敛”这条主线完全做完。
- 可以判定为“功能闭环基本成立，架构收敛部分闭合，不宜标记为完全闭环”。
- 具体到本次要求的 5 个重点：
  - `ONNX launcher` 的 `RTC CLI / runtime override / ActionQueue / real_delay` 已形成闭环，满足上一轮最主要的阻塞项修复要求，证据见 [run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L137)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L191)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L925)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L818)。
  - `TRT launcher` 已经复用了 shared schema 与 prefetch/runtime 基础件，但还没有真正收敛到 shared helper 的 RTC glue，证据见 [run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L33)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1259)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1281)。
  - `shared helper` 已经补上 RTC glue，本体修复成立，证据见 [pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L337)、[pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L429)、[pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L683)。
  - 默认 `RTC off` 现在在 `TRT / ONNX` 两边都成立，且本次复审补跑了最小导入测试：当 checkpoint 自带 `rtc_config.enabled=True` 且未传任何 `--rtc-*` 时，两边都会解析为 `enabled=False`；当仅传 `rtc_execution_horizon=11` 时，两边都会解析为 `enabled=True`。
  - `sync_refill_timeout_s` 的等待语义已经朝设计目标修正，两边都改成了“队列空且存在 future 时先等；等不到才 hold 或 sync refill”，证据见 [run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1739)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1755)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1035)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1048)。

## 已闭合问题

- 上一轮“`ONNX launcher` 没有完成 RTC 接入”的阻塞项已闭合。现在 `ONNX launcher` 已补齐 `--rtc-enable/--rtc-enabled` 及其余 `--rtc-*` 参数，解析 `ResolvedRTCRuntimeConfig`，把 resolved config 写回 `policy_cfg.rtc_config`，并在主循环中用 `ActionQueue`、`compute_real_delay(...)` 与 `ActionQueue.merge(...)` 形成完整 runtime 闭环，见 [run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L137)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L238)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L925)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L999)。
- 上一轮“`ONNX launcher` 不能保证默认 `RTC off`”的问题已闭合。`resolve_rtc_runtime_config(...)` 现在不再跟随 checkpoint 的 `enabled=True` 自动打开 runtime，而是要求显式 `--rtc-*` override 才启用，并在 summary 中对 checkpoint 自带 RTC enabled 但 runtime 关闭的场景打印 warning，见 [run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L191)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L629)。
- `shared helper` 本体已补上 RTC glue，闭合了上一轮“helper 缺少 RTC glue”这项缺口。现在 `pi05_chunk_runtime.py` 已提供通用的 `build_chunk_predict_kwargs(...)` 与 `merge_chunk_prediction_result(...)`，不依赖 launcher 私有 dataclass，也满足 worker A 本轮自述目标，见 [pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L337)、[pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L429)、[worker_a_shared_helper_round2.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_execution_20260314_231604/worker_a_shared_helper_round2.md#L5)。
- `TRT / ONNX` 两边默认 `RTC off` 已同时成立。两边都通过 `resolve_rtc_runtime_config(...)` 做 runtime override，并在构造 adapter 前写回 `policy_cfg.rtc_config`，符合设计里“第一阶段默认仍保持 RTC off，只有显式 RTC CLI 才进入 RTC-aware runtime”的要求，见 [RTC_ACCEL_TECHNICAL_PROPOSAL.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_design_20260314_212932/RTC_ACCEL_TECHNICAL_PROPOSAL.md#L263)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L233)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L191)。
- 上一轮关于 `sync_refill_timeout_s` 分支条件“写反”的问题已基本闭合。当前两边都改成了“`action_queue.empty()` 且存在 future 时先 `wait_for_result(...)`；若 future 仍未完成则 hold；只有没有 future 时才 sync refill”，这与上一轮审查指出的问题相反方向一致，见 [review_architecture_agent.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_execution_20260314_215745/review_architecture_agent.md#L107)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1739)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1035)。
- 上一轮提到的 CLI 命名漂移已闭合。`TRT / ONNX` 两边现在都同时暴露 `--rtc-enable` 与 `--rtc-enabled`，兼容设计文档与既有用法，见 [RTC_ACCEL_TECHNICAL_PROPOSAL.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_design_20260314_212932/RTC_ACCEL_TECHNICAL_PROPOSAL.md#L244)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L176)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L137)。

## 未闭合问题

- `TRT launcher` 没有真正收敛到 shared helper，这一项仍未闭合。虽然它已经从 shared helper 导入了 `AsyncChunkPrefetcher`、`ChunkPredictionResult`、`compute_real_delay`、`estimate_prefetch_threshold`，但仍在 launcher 内保留本地 `build_chunk_predict_kwargs(...)` 和本地 `merge_prediction_chunk(...)`，没有消费 shared helper 新增的 `build_chunk_predict_kwargs(...)` 与 `merge_chunk_prediction_result(...)`。这与 worker B 所称“已改为优先复用 shared helper”并不等价，也没有完全达到 plan 中“共享同一 runtime helper”的目标，见 [worker_b_trt_launcher_round2.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_execution_20260314_231604/worker_b_trt_launcher_round2.md#L6)、[pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L337)、[pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L429)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1259)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1281)。
- 更广义地说，上一轮“两个 launcher 没有真正接入共享 helper”这条主问题只算部分闭合，不算完全闭合。`ONNX launcher` 虽然功能上已经闭环，但同样仍保留本地 `build_chunk_predict_kwargs(...)` 与本地 `merge_completed_chunk(...)`，没有直接复用 shared helper 新增的 RTC glue。也就是说，shared schema / prefetcher 已收敛，RTC glue / merge convenience 仍然是三处维护，见 [RTC_ACCEL_IMPLEMENTATION_PLAN.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_design_20260314_212932/RTC_ACCEL_IMPLEMENTATION_PLAN.md#L13)、[RTC_ACCEL_IMPLEMENTATION_PLAN.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_design_20260314_212932/RTC_ACCEL_IMPLEMENTATION_PLAN.md#L137)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L796)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L818)。

## 风险项

- `RTC glue` 仍然在 shared helper、TRT launcher、ONNX launcher 三处存在并行实现，后续如果只修其中一处，`prev_chunk_left_over`、`inference_delay`、`real_delay` 的语义非常容易再次漂移。这正是实施计划 Step 0 想避免的问题，见 [RTC_ACCEL_IMPLEMENTATION_PLAN.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_design_20260314_212932/RTC_ACCEL_IMPLEMENTATION_PLAN.md#L13)。
- 本轮验证证据仍以静态检查、CLI 检查和最小导入测试为主，没有形成真实 `checkpoint + engine/onnx + robot loop` 的联调证据。worker B 与 worker C 也都明确承认未做真机或硬件在环验证，因此当前结论只能覆盖“架构与代码路径已闭环”，不能覆盖“运行时时序表现已验证”，见 [worker_b_trt_launcher_round2.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_execution_20260314_231604/worker_b_trt_launcher_round2.md#L62)、[worker_c_onnx_launcher_round2.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_execution_20260314_231604/worker_c_onnx_launcher_round2.md#L48)。
- 由于 launchers 还保留本地 merge/glue，shared helper 本轮新增 API 目前更像“可用但未被充分采用”。如果后续团队把 helper 当作唯一真相源继续演进，而 launcher 忘记同步，最先失真的会是 `RTC off/on` 边界条件和 queue merge 口径。

## 建议

- 当前轮次在项目状态上应标记为“主要功能问题已闭合，shared-helper 收敛未闭合”，不要标记为“全部整改完成”。
- 下一步优先把 `TRT / ONNX launcher` 的本地 `build_chunk_predict_kwargs(...)` 与本地 merge wrapper 收敛到 [pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L337) 和 [pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L429)。如果团队有意保留 launcher 本地 wrapper，也应明确写出“为什么不直接复用 shared helper”，否则后续评审仍会把这项视为未闭合。
- 为 `resolve_rtc_runtime_config(...)` 增加最小自动化用例，至少锁定两类场景：checkpoint 自带 `rtc_config.enabled=True` 且未传 `--rtc-*` 时必须保持 `RTC off`；只传单个 `--rtc-*` override 时必须进入 `RTC on`。这是当前默认行为正确性的关键回归点。
- 为 `sync_refill_timeout_s` 增加无硬件的状态机级 smoke test，固定三种路径：future 在 timeout 内完成、future 超时仍 pending、queue 空且无 future。否则这块逻辑后续最容易在重构时再次反向写回去。
- 在进入下一轮“完全闭环”判定前，至少补一轮真实 checkpoint 的 `RTC off` 与 `RTC on` smoke run。当前静态和 CLI 证据已经足够支持架构判断，但还不足以支持“运行结果已经验证”的交付结论。
