# PI05 RTC Round 3 Architecture Review

本报告以当前代码状态为准，不以 worker 自述为准。审查对照了 Round 2 审查材料、Round 3 worker 说明和当前 3 个脚本，并额外独立执行了 `py_compile`、`--help` 和导入级 smoke，核对 shared helper 接线、`0` 值解析、`RTC default-off / override-on` 与 helper fail-fast 契约。

## 结论

- 按代码路径口径，本轮已经达到“功能闭环 + 架构收敛基本成立”的状态，但不建议按“全部问题完全闭合”签收。
- 本轮最大的正向变化是：`TRT / ONNX launcher` 的 RTC glue 主路径已经真正切到 shared helper；shared helper 的静默退化点也已明显收紧；日志解释链路基本成立。
- 仍有 1 项与本轮重点核对直接相关的遗留问题没有完全闭合：`ONNX` 的 `0` 值 CLI 语义只完成了解析层对齐，还没有完成运行期校验层对齐。特别是 `--joint-delta-limit 0`、`--gripper-delta-limit 0`、`--robot-max-relative-target 0` 当前仍与 `TRT` 语义不一致。
- 因此，本轮最准确的判定是：`shared helper` 收敛已成立，功能闭环已成立，日志可解释性基本成立，但 CLI 契约一致性仍有一个需要明确挂账的尾项。

焦点核对结论：

- `TRT / ONNX launcher 是否真正以 shared helper 新 API 为主路径`：是，已成立。
- `ONNX 的 0 值 CLI 语义是否已经和 TRT 对齐`：部分成立，解析已对齐，运行期校验未完全对齐。
- `shared helper 的静默退化风险是否已显著降低`：是，已显著降低。
- `日志能否基本解释 real_delay / refill_mode / sync_refill_count / rtc_enabled`：是，基本可以。
- `还剩哪些不能按“基本收敛”口径通过的项`：核心只剩 CLI `0` 值契约未完全收敛；此外还有真实 runtime smoke 缺失和少量文案/计数口径风险，但后两者更适合记为风险项，不是本轮 shared-helper 收敛的主阻断。

## 已闭合问题

- `TRT launcher` 已真正切到 shared helper 主路径。shared helper 的 `build_chunk_predict_kwargs(...)` / `merge_chunk_prediction_result(...)` 已直接导入并落在 warmup、async collect、async wait、async submit、sync refill 主循环路径中，见 [run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L33)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1607)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1662)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1693)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1705)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1741)。本次代码检索也未再发现 launcher 本地 `build_chunk_predict_kwargs(...)` / merge helper 定义。
- `ONNX launcher` 也已真正切到 shared helper 主路径。shared helper API 已用于 initial sync、async submit、async collect、async wait、sync refill，见 [run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L32)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L920)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L977)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1005)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1016)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1056)。这项是对 Round 2 “shared helper 存在但主路径没走到”的直接闭合。
- `shared helper` 的静默退化风险已明显下降。`build_chunk_predict_kwargs(...)` 在 RTC 未启用但显式传入 RTC-only 字段时不再静默返回 `{}`，而是直接抛 `ValueError`，见 [pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L378)。`merge_chunk_prediction_result(...)` 也不再在 delay 来源不足时伪造 `0`，而是要求显式 `real_delay` 或可靠 action index，上游不满足契约时直接报错，见 [pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L459)、[pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L511)。
- `RTC default-off / override-on` 逻辑继续成立，且本次复核做了独立导入级 smoke。`TRT / ONNX` 两边都仍通过 `ResolvedRTCRuntimeConfig` 将 checkpoint 中的 `rtc_config.enabled=True` 压成 runtime 默认关闭，只有显式 `--rtc-enable/--rtc-enabled` 或其他 `--rtc-*` override 才开启，见 [run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L176)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L233)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L142)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L194)。独立 smoke 也确认了 `TRT default_off=False/override_applied=False` 以及 `ONNX 仅传 --rtc-execution-horizon 11 => enabled=True`。
- `ONNX` 的“`0` 被静默吞成 `None`”这一解析层问题已经闭合。`TRT / ONNX` 两边的 `parse_optional_int(...)` / `parse_optional_float(...)` 现在完全同形，见 [run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L145)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L154)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L111)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L120)。本次独立导入 smoke 也确认了四个返回值分别为 `0 / 0.0 / 0 / 0.0`。
- 日志解释链路已经基本成立。`TRT` 周期日志现在把 `rtc_enabled`、`sync_refill_count`、`refill_mode`、`real_delay` 放到同一条状态线上，且 sync refill warning 会显式打印 `reason`、`prefetch_pending` 与 “`real_delay=0` 仅代表 blocking refill” 说明，见 [run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1644)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1744)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1805)。`ONNX` 周期日志也已经补齐 `sync_refill_count`、`refill_mode`、`rtc_enabled`、`real_delay`，并为 sync refill 单独说明 `real_delay=0` 的语义，见 [run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L959)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1051)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1111)。

## 未闭合问题

- `ONNX` 的 `0` 值 CLI 语义还没有和 `TRT` 完全对齐，这一项不能按“完全收口”算通过。解析层虽然已经一致，但运行期校验层仍有差异。`TRT` 在进入运行前会显式拒绝 `--joint-delta-limit <= 0`、`--gripper-delta-limit <= 0`、`--robot-max-relative-target <= 0`，见 [run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1500)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1505)。而从 `ONNX main()` 当前验证块只校验 action alpha 这一点可以推断，launcher 级别并没有对上述 3 个参数施加同等 guard，见 [run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L817)。同时 `ONNX` 的 clamp 路径会把 `limit <= 0` 当成“不启用限幅”，见 [run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L731)。这意味着相同命令在 `TRT` 和 `ONNX` 上仍可能得到不同结果：`TRT` fail-fast，`ONNX` 继续运行且关闭限幅。这不是 shared-helper 接线问题，但它仍是本轮 CLI 契约收敛未完全闭合的唯一核心尾项。
- `TRT` 的 checkpoint RTC warning 文案仍然比真实规则更窄。当前 warning 只提 `--rtc-enable/--rtc-enabled`，见 [run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1309)，但实际任意 `--rtc-*` override 都会打开 runtime；`ONNX` 文案已经改成了正确表述，见 [run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L638)。这项不阻断“基本收敛”，但仍然是未闭合的小尾巴。

## 风险项

- 目前没有真实 `checkpoint + engine/onnx + robot loop` 的联调或真机 smoke 证据。本轮可以证明“代码路径已闭合、主线设计已收敛”，但还不能证明“真实时序表现已被验证”。worker 文档自身也明确只做了 `py_compile`、`--help` 和轻量 smoke，见 [worker_b_trt_round3.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_execution_20260315_132113/worker_b_trt_round3.md#L11)、[worker_c_onnx_round3.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_execution_20260315_132113/worker_c_onnx_round3.md#L11)、[worker_a2_helper_round3_retry.md](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/docs/results/pi_rtc_accel_execution_20260315_132113/worker_a2_helper_round3_retry.md#L12)。
- `queue_underrun_count` / `hold_step_count` 仍然不是“所有 queue drain 事件”的总计数，而是 hold 路径计数；`sync_refill` 事件是通过新增的 `sync_refill_count` 单独表达的，见 [run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1724)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1814)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1033)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1120)。这已经“基本可解释”，但如果后续有人只盯 `queue_underrun_count`，仍可能误以为没有发生过 blocking refill。
- `wait_for_result(timeout)` 后没有立即再做一次 `maybe_collect()`，因此 timeout 边界仍可能在极窄窗口里多打一拍 hold。这一风险来自 shared `AsyncChunkPrefetcher.wait_for_result(...)` 与 launcher 主循环组合后的边界时序，见 [pi05_chunk_runtime.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/pi05_chunk_runtime.py#L748)、[run_pi05_trt_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_trt_infer_so101.py#L1705)、[run_pi05_onnx_infer_so101.py](/data/tfj/lerobot_tfj/tfj_envs/pi_trt/scripts/run_pi05_onnx_infer_so101.py#L1016)。它不是当前“基本收敛”的阻断项，但仍值得记录为时序边界风险。

## 建议

- 项目状态建议标记为：`代码路径层面的功能闭环 + 架构收敛基本成立，保留 1 项 CLI 契约尾项`。不要写成“全部整改完成”。
- 下一步优先补齐 `ONNX` 与 `TRT` 在 `--joint-delta-limit`、`--gripper-delta-limit`、`--robot-max-relative-target` 上的运行期校验一致性。若团队希望 `0` 表示“显式关闭限幅”，就两边都允许并明确文档；若团队希望 `0` 为非法值，就两边都 fail-fast。当前最糟糕的不是哪种语义，而是两边语义不同。
- 顺手把 `TRT` 的 checkpoint RTC warning 文案改成与 `ONNX` 相同的规则描述，避免操作者误以为只有 `--rtc-enable` 才能打开 runtime。
- 在进入下一轮“完全闭环”判定前，至少补 1 轮真实 artifact smoke：`RTC off` 和 `RTC on` 各跑一次，确认 `refill_mode`、`sync_refill_count`、`rtc_enabled`、`real_delay` 的日志组合与实际路径一致。
- 如果团队后续还要继续演进 shared helper，建议把本轮做过的导入级 smoke 收敛成正式自动化测试，至少锁住 4 件事：`shared helper` 主路径接线、`0` 值 CLI 解析、`RTC default-off / override-on`、以及 helper fail-fast 契约。
